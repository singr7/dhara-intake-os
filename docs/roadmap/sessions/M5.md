## S19 — Pack framework + Radiology Intake Pack

**Required reading:** docs 02 §3.7 (Pack 1 spec), 01 §5 (packs as IP), 06 §8 (pack versioning), 05 §2 (packs tables), 09 §1 (safety in radiology context).

**Tasks**
1. Pack framework: `packs/<key>/` structure = `pack.json` (metadata), `workflow.json` (DSL), `summary-templates/`, `audio/manifest.json`, `harness/` (pack-owned cases), `CHANGELOG.md`. Loader publishes to `packs`/`pack_versions` tables; `POST /workflows/from-pack` instantiates a tenant draft with pack provenance (`packRef`).
2. Author the **Radiology Intake Pack** (the unfair-advantage pack) as DSL sub-flows selected by modality branch:
   - Common: presenting complaint, referring doctor note, prior imaging/reports upload, urgency marker.
   - X-ray: history, pregnancy screening (with sensitive-question UX: text-forward, private phrasing).
   - CT: contrast history, **contrast allergy flow** (prior reactions, severity, premedication history — red-flag on prior severe reaction), renal history question.
   - MRI: **safety screen** — implants/pacemaker/aneurysm clips/metal fragments/claustrophobia (each a red-flag rule with `notify_review`/`alert_staff` severities), prior surgery.
   - All questions en/hi/mr with synonyms; review policy: safety fields `alwaysReview`.
3. Radiologist-ready summary template: structured history block ordered the way radiologists read (complaint → duration → relevant history → safety flags → prior imaging), per doc 02 §3.7. Design a `radiology-intake-output@1` export schema (extends doc 05 §5 fields block) — future Radpretation study association keyed by `patientRef` + accession placeholder.
4. Pack harness cases: ≥ 30 T1 cases including every red-flag rule (pacemaker, severe contrast reaction, possible pregnancy) and tricky phrasings.
5. Console: pack gallery page (browse, version, changelog, instantiate).

**Acceptance**
- Fresh tenant instantiates radiology pack → publishes → phone completes an MRI-safety intake in hi with an implant red flag → reviewer sees safety flags on top → PDF radiologist summary correct; pack harness suite green in CI.

## S21 — Workflow Studio v1: visual builder + simulation

**Required reading:** docs 02 §3.1 (M5 features), 06 (the DSL the builder edits), 07 §1.

**Tasks**
1. Visual flow builder (React Flow) over the DSL: nodes on a canvas with type-specific inspectors (question editor: per-language text with coverage indicators, answer schema editor incl. options/synonyms tables, confirm policy, mode); branch/transition editing with expression builder UI (dropdown field + operator + value, falling back to raw expression input with live validation); red-flag rule editor; review policy panel; output/summary template picker. Builder reads/writes the same DSL JSON (round-trip lossless — JSON view stays available and synced).
2. Server validation surfaced live in-canvas (error badges on offending nodes via JSON-path mapping).
3. Simulation mode: author steps through the flow in a console-embedded runner (real engine against a sandbox session flagged `simulation: true`, excluded from analytics/exports) — shows committed fields + output JSON live; supports injecting transcripts to test interpretation.
4. Version diff view: node-level diff between two versions (added/removed/changed prompts).
5. Guardrails for non-technical authors: publish checklist (coverage, red-flag reachability, review policy sanity), template gallery of common question snippets.
6. Usability pass with a non-engineer (the founder counts): they must build a 5-question flow unaided; note friction in HANDOFF.

**Acceptance**
- The M5 exit demo: non-technical user builds + simulates + publishes a small flow via the visual builder only; round-trip test (visual edit → JSON → visual) lossless in tests; a builder-created workflow runs on a phone.
