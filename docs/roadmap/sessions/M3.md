# M3 — Review console, structured output, exports, analytics v0 · S12–S15

Milestone exit demo: nurse works the queue — confidence badges, red flags, audio snippets, one-click corrections, approve — then webhook + PDF exports fire; analytics v0 shows completion & drop-off.

---

## S12 — Review Console (queue + detail + corrections)

**Required reading:** docs 02 §3.3, 05 §2 (review_actions, field_values), 07 §1 (sessions staff routes), 09 §5.

**Tasks**
1. Review queue page (console): filterable list (`needs_review`, `red_flag`, `low_confidence`, workflow, date), badges, waiting-time sort; live updates (poll or SSE).
2. Session detail: red flags banner on top; field table — value, confidence bar, confirmed-by-patient tick, provenance popover (transcript snippet; audio play button fetching signed URL — **every media access audit-logged** per doc 09 §4); missing/skipped fields section; upload gallery.
3. Corrections: inline edit per field typed by answer schema (same renderers as runner where sensible) → `POST /sessions/:id/corrections` → `review.correction` event + field_values status `corrected` (before/after retained).
4. Actions: approve (→ `reviewed`, `review.approved`), return-to-patient (reopens session with targeted nodes), escalate (flags for admin/doctor attention). Approve blocked while `alwaysReview` fields unviewed or red flags unacknowledged.
5. Red-flag staff notification v1: console banner + queue badge + optional email hook (worker job).
6. Reviewer ergonomics: keyboard navigation, next-in-queue flow, target < 60 s per clean intake.
7. Playwright e2e: queue → correct a field → approve; audit_events show media access + corrections.

**Acceptance**
- A hybrid-voice session from M2 reviewed end-to-end on staging; correction visible in evidence stream and output projection (`review.correctionCount` increments); approve gate rules proven in tests.

## S13 — Summaries + output finalization

**Required reading:** docs 05 §5 (contract — summary secondary), 09 §1 (template-bound generation), 06 §1 (`output` block).

**Tasks**
1. Summary template system: Handlebars-style templates per workflow (`summaryTemplateId`), rendering structured fields → doctor-ready text (en primary; per-tenant language option). Templates versioned in repo/packs.
2. Optional constrained LLM polish step (router `task: summarize`): input = template output + fields only; output re-validated (no new facts: every sentence must map to a field — implement a fact-echo check comparing named values; deny-list filter). Feature-flagged per tenant; template-only is the default.
3. `summary.generated` event with templateId/model/promptVersion/outputHash; reviewer summary editor (edits tracked, `editedByReviewer`).
4. Department routing rule execution (`output.routingRule`): rule-based mapping from fields → suggested department, always `requiresHumanConfirmation: true`; reviewer confirms in console (fills `routing.confirmedBy`).
5. Output projection completed: costs block wired to cost_records, review block, meta (duration, fallbacks, clarifications). Contract snapshot test against doc 05 §5.

**Acceptance**
- Reviewed session produces final JSON passing the contract schema; summary contains no value absent from fields (test); LLM-polish path blocked by deny-list test case.

## S14 — Exports: webhook + PDF (+ export framework)

**Required reading:** docs 07 §6 (webhooks), 02 §3.8, 05 §2 (export tables), 10 §2 (worker).

**Tasks**
1. Export framework in worker: `ExportTarget` kinds registry; jobs enqueued on `review.approved` (per target `active` config) or manual `POST /sessions/:id/export`; `export_records` lifecycle + retries (5, exponential) + console failure alerts.
2. Webhook target: HMAC signature, headers, delivery UUID per doc 07 §6; endpoint test button in console (sends sample payload); events `intake.completed|reviewed|red_flag|deleted`.
3. PDF target: doctor-ready summary PDF (header: tenant branding placeholder, patientRef, workflow+version; fields table with confidence marks; red flags; summary; provenance footnote "collected by DharaIntake, reviewed by <name>"). Decide renderer (`@react-pdf/renderer` vs headless Chromium), record in DEVIATIONS/HANDOFF. Stored as MediaObject (export retention class), downloadable from console.
4. Console: export-targets CRUD (admin), per-session export history with statuses and payload hash.
5. Tests: HMAC verification round-trip, retry/backoff on 500s, PDF snapshot (structure-level), export blocked for non-reviewed sessions when policy requires review.

**Acceptance**
- Approving a session on staging fires a webhook to a test receiver (signature verified) and produces a downloadable PDF; failure path (dead URL) shows failed record + alert after retries.
