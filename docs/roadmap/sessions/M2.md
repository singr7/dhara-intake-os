# M2 — Hybrid voice + touch runner · S07–S11

Milestone exit demo: the OPD intake completed by *speaking* answers in Hindi/English — cached prompt audio, streaming STT, interpreted-answer confirmation, clarification loop, automatic touch fallback — with every voice step in the evidence graph. Mode 2 only; no realtime speech-to-speech (that's M7).

---

## S07 — Provider adapter layer (STT/LLM/TTS interfaces + first implementations)

**Required reading:** docs 08 §1–2, §4 (adapters, routing), 03 (ADR-008, 009), 04 stack table.

**Tasks**
1. `packages/providers`: define `SttAdapter`, `LlmAdapter`, `TtsAdapter`, `RealtimeAdapter` (interface only for now) exactly per doc 08 §2, plus `Paise` money type and `usage` shapes. Lint rule: provider SDK imports allowed only inside `packages/providers/src/impl/*`.
2. Implement first adapters (verify current model ids/pricing at build time; record chosen models in HANDOFF):
   - STT: Google STT v2 streaming (en/hi/mr) + one en-focused alternative (Deepgram or OpenAI whisper-class). Partials + finals + confidence + language detection.
   - LLM: Gemini Flash `extract()` with JSON-schema-constrained output; OpenAI mini-class as fallback impl. `extract` returns `{value, confidence, usage}`; refusal/format failure → typed error.
   - TTS: Google TTS (en/hi/mr voices) returning PCM/opus buffer.
3. Router service (`apps/api/modules/router`): resolves `(kind, {lang, task, mode, tenant})` → adapter chain from `routing_policies` (doc 08 §4 JSON rules); walks fallbacks on failure/timeout emitting `fallback.triggered`; records `cost_records` (+ `cost.recorded` event) and latency for every call. Seed platform-scope policy rows.
4. Env additions (Zod env): provider keys; `/health` reports per-provider key presence + a cheap connectivity probe flag (demo lesson).
5. Contract tests with recorded/mocked provider responses; one gated live smoke test per adapter (`RUN_LIVE_PROVIDER_TESTS=1`).

**Acceptance**
- Unit+contract tests green without keys; live smoke green with keys (run once, note in HANDOFF).
- Router fallback proven in test (primary adapter throws → fallback used → `fallback.triggered` + two cost_records written).

## S08 — Prompt-audio pipeline (record/render/cache/serve)

**Required reading:** docs 08 §3 (prompt side), 05 §2 (prompt_audio, media_objects), 06 §6, 03 (ADR-016).

**Tasks**
1. Prompt audio resolution service: `(workflowVersion, nodeId, lang, voice)` → recorded file → TTS cache by contentHash(text+lang+voice) → live TTS (logged cache-miss). Files stored as opus in S3 (`audio/prompts/...`), indexed in `prompt_audio`.
2. Worker job `tts-prerender`: on workflow publish, enumerate all prompts/labels/clarifications × declared languages → render+cache anything missing; report coverage.
3. Signed/public-cacheable prompt URLs (immutable, hash-addressed → long cache headers via nginx).
4. Pack manifest support: `packs/*/audio/manifest.json` maps nodeId+lang → human-recorded files; import tool uploads to S3 and registers as `source: recorded` (preferred over TTS).
5. Studio v0 addition: per-workflow audio coverage panel (rendered/recorded/missing per language) + "re-render" button.
6. Step envelope now includes real `prompt.audioUrl`; `prompt.played` event emitted by runner (batched beacon).
7. Tests: cache-hit path does zero TTS calls (assert via adapter spy); publish triggers prerender job; content change → new hash → new render.

**Acceptance**
- Publishing OPD workflow yields 100% hi+en audio coverage; repeated publishes with unchanged text render nothing new; runner receives working audio URLs.

## S09 — Runner voice capture + STT streaming

**Required reading:** docs 08 §6 (client pipeline — port demo lessons), 07 §4 (`/ws/stt`), 02 §3.2 hybrid features.

**Tasks**
1. Port + rewrite in TS from demo (`src/voice.js`, `src/live-audio.js` patterns): shared `AudioContext` + `unlockAudio()` on consent tap (gesture already reserved in S05); AudioWorklet capture → 16 kHz PCM16 → 100 ms frames; client energy VAD gating; `maxUtteranceSec` stop; wake lock acquire on session start / release on completion.
2. `/ws/stt` relay in API: token+nodeId auth → router-resolved STT adapter stream → `{partial|final, transcript, confidence, langDetected}` downlink; terminates on final/silence/max-window; writes `answer.audio_captured` (uplink audio also saved to S3 as MediaObject, respecting retention class) + `answer.transcribed` events.
3. Runner question screen hybrid UI: play prompt audio → mic button with live level meter + partial transcript display → on final, show "did you say …?" interpretation placeholder (real interpretation S10) with Confirm / Say again / Type instead controls.

5. Mic permission UX: pre-permission explainer; denial → touch mode gracefully.
6. `PROVIDER_UNAVAILABLE` on WS → runner silently degrades that node to touch (doc 07 §7 rule).
7. Playwright test with fake media stream (Chrome `--use-fake-device-for-media-stream` + WAV fixture) driving one voice answer end-to-end.

**Acceptance**
- On a real phone: speak "five days" (en) → transcript appears < 1.5 s after utterance end → confirm → field committed with voice provenance incl. audio MediaObject ref.

## S10 — Interpretation ladder (deterministic parse → LLM extraction → clarification)

**Required reading:** docs 06 §3 (extraction ladder — binding), 08 §3, 05 §4 (answer.* events), 09 §1 (constrained LLM use only).

**Tasks**
1. Deterministic parsers per answer type (`packages/dsl/parse`): choice/multiChoice synonym matching (per-lang synonym lists incl. transliteration variants), boolean synonyms (haan/nahi/ho/nako…), number + numeral-words (en/hi/mr up to 9999), duration ("paanch din", "two weeks"), date (absolute + relative), phone/id regex. Confidence heuristics (exact=0.98, fuzzy tiers). Extensive unit tests — this is where most answers must terminate (cost rung 1–2).
2. LLM extraction service: builds tiny per-node prompt (question text, answer schema, transcript, lang) → `LlmAdapter.extract` with Zod schema `{value, confidence, ambiguity[]}`; prompt templates versioned in-repo (`promptVersion` recorded in `answer.interpreted`); intake-only system contract + deny-list post-filter on any echoed text.
3. Interpretation orchestrator on `/run/answer` (kind=voiceRef): ladder rungs 1→3, then clarification (`clarification.asked`, re-ask with cached clarification audio, ≤ `clarificationMaxAttempts`), then touch fallback, then skip+missing-flag per DSL. Confidence < node/review threshold → `confirm: always` behavior.
4. Ambiguity/contradiction handling: LLM `ambiguity[]` markers stored; contradictory with earlier field → clarification citing neither value (just re-ask), `validation` warnings recorded.
5. Proxy-speaker heuristic v0: langDetected mismatch or "my father…" patterns → provenance `speaker: proxy?` marker (full detection later).
6. Test matrix (seed of the future harness, keep as fixtures under `harness/cases/opd-general/t1/`): clean/partial/rambling/code-switched/contradictory/"I don't know" transcripts per answer type × en/hi.

**Acceptance**
- Fixture suite: ≥ 95% of clean cases resolved at rung ≤ 2 (no LLM call — assert via adapter spy); ambiguous cases produce exactly one clarification then resolve or fall back; zero commits without confirmation when confidence < threshold (tests).
- End-to-end voice OPD intake in Hindi commits correct normalized values.
