# M1 — Workflow spine (deterministic intake, no voice) · S01–S06

**Required reading:** doc 06 (all — this session implements it exactly), 05 §2 (workflow tables).

**Tasks**
1. `packages/contracts`: Zod schemas for the full DSL document (doc 06 §1–3, §5), all node types, all answer schema types, expression strings as branded type.
2. `packages/dsl`: expression grammar parser (doc 06 §4) → AST + evaluator with typed context `{f: fields}`; **no eval**. Exhaustive tests incl. precedence, functions, type errors.
3. `validate(doc)` per doc 06 §7: shape, unique ids/fieldKeys, reachability, all-paths-terminate, cycle check, expression type-check against field types, field-before-use topological check, language coverage (warn draft / error publish), deny-list scan of patient-facing strings (seed deny-list file `packages/dsl/denylist.ts`: diagnos*, prescri*, treatment, "you have", disease names list placeholder), review-policy reference check. Output `{errors[], warnings[], compiledGraph}` with human-readable messages + JSON paths.
4. `compiledGraph`: adjacency map + precompiled ASTs + per-node metadata (answer type, confirm policy, modes).
5. Interpreter core (pure, no I/O): `nextNode(compiledGraph, committedFields, currentNodeId)` and `evaluateRedFlags(...)` — the session engine (S04) will drive it.
6. API workflow module: routes from doc 07 §1 Workflows block (list/create/get/draft PUT/validate/publish; from-pack + packs routes may 501 until M5). Publish freezes version, bumps semver per doc 06 §8, writes `workflow_versions`.
7. Author the **first real workflow**: `packs/opd-general/workflow.json` — trimmed OPD flow (consent → chief complaint (choice) → duration (duration) → fever/cough/pain booleans with one branch → existing conditions (multiChoice) → medications (text) → allergy (boolean+text) → red-flag rule (e.g. chest_pain && breathlessness → high) → end), en+hi text, all-touch modes. It must pass validation with zero errors.
8. Tests: validator fixture suite (valid doc, each error class), interpreter path tests over the OPD doc.

**Acceptance**
- `POST /workflows` + draft PUT + validate + publish round-trip works via curl using the OPD doc; second publish bumps version; published version immutable (test).
- Validator catches: unreachable node, missing language string on publish, expression referencing uncommitted field, deny-list violation. All in tests.

## S04 — Session engine + runner API (state machine, touch answers, evidence)

**Required reading:** docs 05 §3–5 (states, events, output contract), 07 §2–4 (runner API, step envelope, /ws/run), 03 (ADR-006, 010), 09 §2.

**Tasks**
1. Session module: state machine exactly per doc 05 §3; transitions only via `transition(sessionId, to, reason)` emitting `session.state_changed`; illegal transition → `INVALID_TRANSITION` problem.
2. `POST /sessions` (staff): creates session pinned to workflowVersion, mints intake token (short-TTL signed, scope = session; rotate on state change per doc 09 §4), returns joinUrl + QR SVG endpoint (port demo QR approach).
3. Runner routes (doc 07 §2): `/run/session`, `/run/consent` (writes ConsentRecord + events; granted → `in_progress`; declined → assisted handoff state), `/run/step` (build step envelope per doc 07 §3 from compiledGraph — touch UI schema per answer type: choice grid, boolean, number pad, duration picker, text, multi-choice), `/run/answer` (touch kind only this session → validate against answer schema → `answer.touch` + `field.committed` events → red-flag eval → transition/next), `/run/confirm`, `/run/abandon`, `/run/assist`.
4. Snapshot maintenance on `intake_sessions.snapshot` (answers, retry counters) so sessions resume after refresh/network drop.
5. Field projection: on commit, upsert `field_values` with provenance `{method:'touch', eventIds}`.
6. Terminal node → output projection builder producing **exactly** doc 05 §5 contract (costs zero for now) stored on session; state → `completed`.
7. `/ws/run` step-stream channel (server push of step/state) with HTTP fallback preserved.
8. Red-flag escalation: `high`+`alert_staff_immediately` → `human_assistance_needed` + placeholder staff notification (log + DB row; console UI comes M3).
9. Integration tests driving the OPD workflow start→completed via HTTP: happy path, branch paths, red-flag path, resume-after-restart, consent-declined path, token expiry.

**Acceptance**
- Full curl-scripted intake reaches `completed`; `GET /sessions/:id` shows fields with provenance + full ordered event stream matching doc 05 §4 names.
- Output JSON validates against a Zod schema of doc 05 §5 (test).
- No question obtainable in any state without granted consent (test).
