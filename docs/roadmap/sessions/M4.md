## S16 — Cost metering completion + budgets + cost-aware routing

**Required reading:** docs 08 §4–5 (binding), 05 §2 (cost_records, budgets), 02 §3.4.

**Tasks**
1. Audit every adapter call path for cost coverage: STT seconds, LLM tokens, TTS chars (cache hits = 0), with paise conversion tables in `provider_configs` (prices are config, not code — they drift). Session `costTotalPaise` maintained transactionally.
2. Session caps from DSL `settings` (`maxCostPaise`, `maxDurationSec`): on breach → event + degrade to touch-only for remaining nodes (capture never stops); realtime kill semantics stubbed for M7.
3. Tenant budgets: monthly rollup vs `budgets.capPaise`; soft alert (console + email) at pct; hard stop → all tenant sessions forced touch-only + admin banner. Worker job + tests with simulated spend.
4. Cost-aware routing: router honors `priority` + per-call `priceEstimate` when policies mark a step `costSensitive`; per-workflow cost report endpoint (`GET /analytics/costs`) — by kind, provider, workflow, day; **cost per completed intake** headline tile + per-mode breakdown on analytics page.
5. Latency tracking surfaced: p50/p95 per provider per day (from cost_records.latencyMs).
6. Tests: budget hard-stop flow, cap-degrade flow, price-table change affects estimates not history.

**Acceptance**
- Dashboard shows ₹/completed-intake for the dogfood corpus with plausible decomposition; forcing a 1-paise tenant cap on staging flips new sessions to touch mode with correct UX copy.

## S17 — Audit completeness, retention engine, DPDP workflows

**Required reading:** docs 09 (all), 05 §6 (retention clocks), 07 §1 (DELETE /sessions/:id).

**Tasks**
1. Audit sweep: verify every doc-09 §4 listed action writes `audit_events` (login, session view, media access, export, deletion, config/key change, budget change, workflow publish). Add missing. Platform-ops audit viewer page (filterable, read-only).
2. Retention engine (worker, daily): three clocks from tenant settings — expire audio MediaObjects (S3 delete + row tombstone), redact transcripts in evidence payloads (`{redacted:true, sha256}` hash-preserving), structured-data expiry per contract. Dry-run mode producing a report first; then enforce. Retention settings UI (tenant admin) with guardrail minimums.
3. DPDP data-principal flows: per-session purge (`DELETE /sessions/:id` → hard-delete media, redact events, tombstone session, audit + `intake.deleted` webhook) and per-session export (structured contract JSON + consent record) from console.
4. Log hygiene verification: pino redact paths tested (transcripts/PII never in logs — test asserts on captured log output); nginx access logs reviewed for token leakage (tokens in headers only — fix any URL-token usage except signed media URLs which expire).
5. Backup automation: nightly `pg_dump` to S3 + verify script; document restore procedure in `infra/RUNBOOK.md` (drill happens S24).
6. Tests: retention clocks (fixture sessions aged artificially), purge completeness (no orphan S3 objects — checker script), redaction preserves event seq/hash integrity.

**Acceptance**
- Aged fixture session: audio gone, transcripts redacted, structured data intact, evidence chain still verifiable; purge of a session leaves zero PII (checker green); audit viewer shows the whole story.
