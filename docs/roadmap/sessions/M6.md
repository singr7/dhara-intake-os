## S23 — Kiosk mode + Assisted-intake mode (Mode 4)

**Required reading:** docs 02 §3.2 (kiosk, assisted), 01 §4 (Mode 4), 09 §4 (kiosk safety), 05 §4 (assistance events).

**Tasks**
1. Kiosk mode: kiosk device pairing (operator pairs a device to tenant+workflow via code — generalize the demo's join-link pairing), attract/ready screen, auto session creation per patient, hard wipe between sessions (storage + memory), inactivity timeout → confirm → wipe, no browser chrome escape (PWA fullscreen; Android kiosk app itself is M8/M10).
2. Assisted-intake mode (Mode 4): operator device runs the intake *with* the patient — operator sees the question + a live structuring panel; system listens to the operator-patient exchange per question (same STT path), extracts, operator confirms/edits each field inline; `assistance.provided` provenance (`method: assisted`). Missing-field prompter at the end. This is deliberately question-by-question (not free conversation) — same state machine.
3. Runner "call for help" → operator notification (console + sound) with session takeover into assisted mode mid-flow, resuming at current node.
4. Session handoff continuity tests: patient starts hybrid → assist requested → operator completes → review shows mixed provenance correctly.
5. UX pass for queue pressure: 10-second resume, no dead-ends, every screen has a staff-recoverable path.

**Acceptance**
- Kiosk loop: 3 consecutive strangers complete intakes with zero cross-session leakage (checker + manual); assisted mode completes an intake with per-field operator confirmations in the evidence graph.

## S24 — Load, failure hardening, restore drill

**Required reading:** docs 10 §4–7 (load targets, ops), 08 §1 principle 5 (degrade never dead-end).

**Tasks**
1. k6 load suite (`infra/load/`): scripted hybrid intake (steps + STT WS with synthetic audio) — target 50 concurrent sessions, p95 step < 2 s on the omen box. Profile and fix hotspots (likely: event insert contention, envelope build, S3 signing).
2. Chaos pass: kill each dependency (redis, minio, each provider, worker) under load — verify degradation matches design: provider down → touch degrade; redis down → capture continues (queue-dependent features defer); worker down → exports backlog + alert, intake unaffected; S3 down → voice degrades (no audio store), touch continues. Fix violations.
3. WS robustness: reconnect storms, phone sleep/wake mid-session (demo lesson: visibilitychange re-establish), token rotation race conditions.
4. Backup **restore drill**: restore staging from last night's dump onto a scratch instance, verify integrity checker; document timing in RUNBOOK.
5. Security pass: dependency audit, header hardening (CSP for console/runner), upload AV hook (clamav container), rate limits verified under load, secrets sweep of repo history.
6. Alert tuning from load-test noise; on-call notes in RUNBOOK.

**Acceptance**
- k6 report meeting targets committed to `infra/load/reports/`; chaos matrix table in RUNBOOK with all cells "degrades as designed"; restore drill documented with timing; zero criticals from security pass.
